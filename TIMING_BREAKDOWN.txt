┌─────────────────────────────────────────────────────────────────────────────┐
│ KEY TAKEAWAYS                                                               │
└─────────────────────────────────────────────────────────────────────────────┘

1. CNN IS CHEAP RELATIVE TO OPTIMIZATION
   • CNN inference: ~700 ms (one-time)
   • PLM optimization: ~250-400 ms per iteration
   • Adding CNN to hybrid costs only ~15% overhead

2. EARLY ITERATIONS ARE GOLDEN
   • First 20 iterations = 65% quality recovery
   • Time spent: only 12% of full PLM (6.7 sec vs 51.8 sec)
   • Efficiency: 0.43 dB per second (best bang-for-buck)

3. OPTIMIZATION TIME DOMINATES
   • For CNN + 20 iter: 89% of time is PLM, 11% is CNN
   • Not worth optimizing CNN to be 100ms faster
   • Worth optimizing PLM to be 1000ms faster

4. SWEET SPOT IS 20 ITERATIONS FOR INTERACTIVE
   • 6.7 seconds total (reasonable wait)
   • 4.93 dB quality (65% of full gap recovered)
   • Still efficient (0.43 dB/sec)
   • Users accept 6-7 second wait for interactive app

5. DIMINISHING RETURNS KICK IN FAST
   • 10→20 iter:  +0.64 dB for +2 seconds
   • 20→50 iter:  +0.75 dB for +7 seconds
   • 50→100 iter: +0.35 dB for +12 seconds
   • 100→200 iter: +0.27 dB for +25 seconds

6. TIME/QUALITY EFFICIENCY PEAKS AT 10 ITERATIONS
   • 0.001089 dB/ms best ratio
   • But only provides 4.29 dB (50% recovery)
   • Not practical alone; use as stepping stone
